# 專題面試說明資料：AI 台股選股排行與回測平台

> 用途：面試時介紹此專題的講稿與問答備忘。內容皆來自專案 README、`docs/` 與程式碼，數字以 `README.md` 為準。
> 原則：**誠實呈現結果與限制**。這個專題最有價值的地方不是「績效很好」，而是「怎麼避免自己騙自己」。

---

## 1. 三十秒版本

> 我做了一個台股選股系統：用 LightGBM 預測 64 檔股票未來 20 日報酬，每期買進預測最高的 10 檔，和 0050 比較。
> 回測 65 期，扣掉交易成本後平均每期贏 0050 約 2.04 個百分點，信賴區間下界為正。
> 但我同時做了穩健性檢驗，發現模型並沒有明顯贏過簡單的動能策略，也有存活者偏差，所以我把結果定位成「偏樂觀的上限」，並另外建立每日前瞻追蹤來累積真正的樣本外證據。

## 2. 兩分鐘版本

1. **問題**：機器學習選股能不能在扣除成本後穩定贏過大盤 ETF（0050）？
2. **做法**：12 個價量技術特徵 → LightGBM 預測 20 日報酬 → 每約 28 天選 Top-10 等權持有 → 單邊成本 0.1%。
3. **驗證**：65 期非重疊回測；bootstrap 95% 信賴區間；walk-forward、20 日 embargo、保留期；和動能基準（mom20）對照。
4. **系統**：Django 網站 + MySQL，每日自動更新股價、還原價、前瞻預測、到期評估，網頁可看排名、回測、前瞻績效。
5. **風控延伸**：發現大跌期表現差，設計 0050 跌破 200 日均線就降到 50% 持股的濾網。參數事先寫入文件才看結果。
6. **結論**：回撤從 -31.9% 降到 -23.3%，但平均超額少 0.34 個百分點，且統計上不顯著，所以我不宣稱濾網有效，只當參考。

## 3. 專題亮點（面試重點）

### 3.1 資料與避免偏誤（最值得講）

| 問題 | 我的處理 |
|---|---|
| 高股息 ETF 除息會造成假性下跌 | 模型與評估統一使用**還原價**；還原價不完整或落後時**中止**，不用錯誤資料排名 |
| 流動性過濾若用最新一天決定整檔股票，會有前視偏誤 | 改成**逐日過濾** |
| 基準同時當選股標的 | 0050 只當基準，不列入候選 |
| 重疊期間造成報酬自相關、高估顯著性 | 採**非重疊**取樣（28 日曆天） |
| 訓練與驗證資料的標籤重疊 | walk-forward 加 **20 日 embargo** |
| 前瞻紀錄被事後改寫 | 資料庫有唯一鍵，**同日同檔同版本不重寫**（快照模式），並有測試保護 |

### 3.2 統計思維

- 不只看平均，還報 **95% 信賴區間**（bootstrap）。
- 用 **RankIC**、方向準確率評估排序能力，而不只看報酬。
- 與簡單基準（5 日反轉、低波動、mom20 動能）比較，檢驗 ML 是否真的有附加價值。
- 結果：ML 相對動能基準的差異，信賴區間**包含 0**，所以不宣稱 ML 明顯優於動能。

### 3.3 研究紀律：事前登記參數

做空頭濾網時，先寫 `docs/BEAR_FILTER_PLAN.md`，固定 MA200、持股 50%、成本、評估方法與限制，**看結果前就定案**，並規定不得因結果調參。結果不理想也照實公布。

### 3.4 工程面

- Django + MySQL；股票池存在資料庫，網頁新增股票即背景抓歷史資料、重算還原價、納入模型。
- 單檔與批量新增**共用同一佇列**，避免同時抓取；遇到 428 限流會冷卻與停止。
- 每日流程腳本任一步失敗即中止，日誌寫檔，同日不重複執行。
- 新版本（V5.9-MA200F）以**獨立檔案與獨立輸出**實作，不修改既有 V5.1／V5.9／前瞻程式與輸出。
- 測試：33 項（新增股票流程、還原價檢查、空頭濾網邏輯與無未來資料洩漏、前瞻紀錄寫入）。
- 文件：README（研究結論）、`PROJECT_OVERVIEW.md`（維護手冊）、`BEAR_FILTER_PLAN.md`（事前規劃與結果）、`OPTIMIZATION_PLAN.md`（優化與風險評估）。

## 4. 主要結果（誠實版）

**V5.9：Top-10 vs 0050（65 期，2021-08-03 至 2026-10-02）**

| 指標 | 數值 |
|---|---|
| Top-10 平均 20 日報酬 | 4.30% |
| 0050 平均 20 日報酬 | 2.13% |
| 淨超額（扣單邊 0.1% 成本） | +2.04%，95% CI [+0.53%, +3.54%] |
| 勝過 0050 的期數 | 44／65（67.7%） |
| 最大回撤（扣成本） | -31.94% |

**空頭濾網 V5.9-MA200F（參考）**

| 版本 | 平均淨超額 | 最大回撤（淨） |
|---|---|---|
| V5.9 | 2.04% | -31.94% |
| MA200 濾網（空頭持股 50%） | 1.70% | -23.31% |
| 敏感度：空頭全現金 | 1.37% | -16.85% |

- 兩者超額差 -0.34%，CI [-1.01%, +0.33%]，**不顯著**。
- 大跌 6 期中只有 3 期事前發出訊號；大漲期因減碼少賺。
- 濾網不改變選股，所以 RankIC 與方向準確率不變。

**一句話解讀**：濾網降低了最大回撤，代價是少賺一些報酬；但樣本太少，不能說它一定有效。

## 5. 限制（主動說出來比被問到好）

1. **存活者偏差**：股票池是「現在」的 64 檔，回推歷史只含存活股票，超額報酬偏樂觀。目前沒有歷史成分股資料，無法在程式中修正。
2. **樣本少**：65 期，其中大跌只有 6 期，空頭結論統計力很弱。
3. **ML 未明顯優於動能**：穩健性檢驗中差異不顯著。
4. **成本簡化**：單邊 0.1% 固定，未含滑價與證交稅細節。
5. **資料起點 2021**：沒有更長期（例如含 2008 金融海嘯）的資料，不能宣稱涵蓋完整景氣循環。
6. **濾網僅回測**：尚無前瞻驗證；也不同於「能實際賺錢」的保證。

## 6. 常見面試問題與建議回答

**Q1：這個策略真的能賺錢嗎？**
回測有正的淨超額，但有存活者偏差與樣本少的問題，我視為偏樂觀的上限。所以我另外建立每日前瞻追蹤，用時間累積真正的樣本外證據，而不是相信回測。

**Q2：怎麼避免未來資料洩漏？**
（1）逐日流動性過濾；（2）walk-forward 加 20 日 embargo；（3）濾網只用 t 日（含）以前的收盤與 MA200，並有測試驗證截斷未來資料後訊號不變；（4）前瞻紀錄用快照模式，不事後改寫。

**Q3：為什麼不調參數讓空頭濾網表現更好？**
樣本只有 65 期、大跌 6 期，調參幾乎一定過度擬合。我事先把參數寫進文件並固定，結果不理想也照實公布，這比好看的數字更可信。

**Q4：濾網有效嗎？**
回撤明顯改善（-31.9% → -23.3%），但報酬略降，差異不顯著，且 6 次大跌只有 3 次事前偵測到。我的結論是「有降低風險的跡象，但證據不足」。

**Q5：為什麼用 LightGBM？**
表格型特徵、資料量中等、訓練快、可處理非線性。同時我也用簡單動能基準檢驗，確認複雜模型有沒有真的帶來價值。

**Q6：用了哪些特徵？**
12 個：1／5／20 日報酬、5／20／60 日均線比、RSI、成交量變化與量比、20 日波動度、上市／上櫃標記。

**Q7：最大的技術挑戰？**
資料正確性：還原價（除權息）、股價缺漏、抓取限流。我的做法是「不完整就中止、不覆寫舊檔」，寧可流程停下來，也不要悄悄用錯資料產生結果。

**Q8：如果再給你時間會做什麼？**
取得歷史成分股以處理存活者偏差；加入月營收等基本面特徵（以公告日對齊）；擴充更長期資料；補自動化測試與 CI。優化清單與風險評估在 `docs/OPTIMIZATION_PLAN.md`。

**Q9：你自己做了哪些部分？**（請依實際情況回答）
建議說明：資料流程、模型與回測設計、事前登記的濾網研究、網頁與測試。若使用 AI 工具輔助，可坦白說明你負責設計決策、驗證結果與理解每個結論的限制。

**Q10：學到什麼？**
金融資料的核心不是模型多強，而是**驗證方法**：非重疊、信賴區間、事前固定參數、誠實面對限制。
